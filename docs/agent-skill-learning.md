# 网页任务结束时的站点经验检查

## 问题与目标

2026-10-23 在浙学作业任务中，首次读取的祖先容器混入多道题，改为按独立题目容器分组后完成任务。但 Agent 直接 browser_finish，没有调用 Skill 写入工具。已有写入能力和提示词，不等于存在可靠的收尾检查。

目标：主 Agent 在多步网页任务收尾时检查增量经验，有证据才称已保存；不恢复题卡/解析器，不更改写入权限，不为学习重复操作网页。

## 实施流程

1. 只检查当前助手回合的工具记录，不把以前回合的读写当作本轮证据。外部站点至少两次成功操作才启动检查，普通问答、单步操作、本地导航不额外调用模型。
2. 失败后同类操作成功、不同的读取脚本都返回成功，均作为候选经验提示，而非把“工具成功”当作内容已经验证。候选的复用价值和语义正确性仍由模型基于实际观测判断。
3. browser_finish(done) 接收 learning.decision 和具体 reason：updated、covered、no_new、deferred。blocked、watching、子 Agent 和用户中止不强制学习。
4. updated 需有本轮先读后成功写入当前站点文件的记录；不存在的文件可在读到不存在后新建。covered 需成功读取，不能把不存在的文件算覆盖。候选经验不能直接 no_new。
5. site-learn 的站点主文档写入前，宿主检查本轮确实读取过原文件。模型应保留既有正文、合并增量。相同正文直接返回 unchanged，不重复保存或请求授权。
6. 保持 allow / ask / deny 策略。拒绝授权或写入失败可 deferred，必须报告未保存；不重复申请。默认 ask 不变。
7. 清单已完成或已有收尾检查记录，模型仍直接口头结束时，runner 的 beforeComplete 接入检查，最多补两轮；轮次预算已耗尽则直接记录暂未检查，不追加请求。显式 finish 连续两次检查不完整后允许任务收尾，但将学习标为 deferred。不能无限阻塞已经完成的网页任务，也不能把超限当作写入成功。
8. 收尾工具返回可审计的 decision、reason、path 和少量工具 ID；不回灌完整网页或整段对话。失败的隐式检查会在最终答复附上未确认保存说明。

## Skill 内容边界

记录页面范围、结构关系、可靠定位方法、验证方式和失败边界；复用已有内容时跳过重复更新。只用题目容器内的题干、选项和控件建立关联，不保存具体答案、账号、密码、验证码、临时 ref、固定题数或未经验证的长度阈值。内置在浙学文件补充了本次观察到的归题问题和校验要求；用户已有覆盖文件不会被强制覆盖。

## 验证与限制

回归覆盖：本轮读取修正、失败恢复、常规流程跳过、错误站点/旧回合证据、先写后读、长参数截断、文件不存在、重复正文、写入拒绝/失败、策略 deny、直接结束的次数上限和普通问答无额外请求。

记录核对只能验证读写行为，无法证明经验文本的语义必然正确。宿主不根据原始网页自动执行生成的脚本或生成所谓正确答案。任务终止和接管仍立即取消当前回合，不为保存经验另起后台任务。
