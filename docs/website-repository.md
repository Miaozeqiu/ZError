# 网站仓库与本地分支

学习通默认使用公开仓库 `Miaozeqiu/ZError-chaoxing` 的 `skills/chaoxing/`，在浙学默认使用 `Miaozeqiu/ZError-zjooc` 的 `skills/zjooc/`。设置页支持导入其他公开 GitHub 网站仓库。每个网站独立保存来源、缓存、本地分支和冲突；未关联仓库的站点继续沿用现有的站点存储。客户端不包含维护者的 GitHub Token，不调用系统 Git，也不执行下载的脚本。

## 导入格式

在仓库根目录、`skills/<id>/` 或 `.agents/skills/<id>/` 提供 `website.json`：

```json
{ "version": 1, "id": "zjooc", "name": "在浙学", "host": "zjooc.cn", "icon": "assets/icon.ico" }
```

同目录必须有 `SKILL.md` 和 `site-graph.json`。Skill 的 name、图谱 id 与网站 id 一致，图谱 host 与网站 host 一致。图标必须在仓库内 `assets/` 下，支持 PNG、ICO、JPEG、WebP、GIF，最多 256 KiB；验证文件哈希、真实图片格式和原生解码，不接受外链、SVG 脚本或 HTML 错误页。图标单独缓存，不混入 Agent 的经验正文与模型上下文。

用户在「设置 → Agent → 网站 → 导入 GitHub 仓库」填写 `owner/repo`、仓库首页链接或 `tree/<分支>/skills/<id>` 链接。程序发现候选网站后展示名称、域名与仓库内图标，用户确认后按预览时的提交 SHA 导入完整快照；多个网站包可选择。默认分支从 GitHub 元数据读取。目录链接的带斜线分支名暂不支持，可使用仓库首页链接发现。

预览不落盘，导入前下载和验证完整快照。既有同一来源可更新；相同域名关联了另一来源时拒绝静默替换。导入不会自动关联登录域名、授权凭据或修改账号。旧的单站加密文档会迁为多站索引，保留学习通原分支；跨网站写入通过共享队列串行持久化，避免丢失另一站的修改。

## 读取

`websiteRepositoryGitHub.ts` 通过匿名只读 HTTPS 请求获取一次提交及其完整目录，再按该提交关联的 blob SHA 下载文档。下载核对 blob 的实际字节数、Git blob SHA-1、UTF-8 和入口/图谱结构。只接受 `SKILL.md`、`site-graph.json`、`references/<名称>.md`，拒绝路径穿越、符号链接、可执行文件、截断目录和超限文件；任一文件失败都不替换原缓存。

快照最多 32 文件、每文件 512 KiB、合计 2 MiB。原生客户端优先使用已经完整加载的缓存，后台最多每六小时检查一次，使用 ETag 减少重复下载；用户可以手动检查更新。超时、限流或断网时保留完整缓存，遵守服务返回的重试时间，不循环重试。首次离线且没有远端缓存时使用随应用附带的离线副本，设置中明确显示来源。

## 本地修改

应用管理的是本地派生分支，不是在 GitHub 账户上创建远程 Fork，也不是伪装成 `.git` 目录。第一次修改创建分支 ID，保存父版本、每个改动文件的原文、当前内容与冲突状态。因此普通用户无需安装 Git 或登录 GitHub。此版本不提供自动上传、推送或 PR。

上游快照和本地分支保存在原有系统密钥保护的加密文档 `website_repositories` 中；不以明文 localStorage 或新的 Skill 覆盖文件保存正文。旧本地学习通覆盖文件首次迁入本地分支，原文件保留，不自动删除；迁移标记避免恢复官方版本后再次导入旧修改。读取、迁移或保存失败时不发布假成功状态。

上游未改动的文件直接更新。本地修改和新上游改到同一文件时，保留本地内容并标记冲突；不尝试自动推测文本含义。用户可比较官方内容后选择保留本地、采用官方，或编辑后保存合并结果。不同文件的修改互不覆盖。下载在写入队列之外进行，提交新快照时再合并最新本地状态，保护下载期间发生的修改。

界面编辑和 Agent 文件读取返回版本号，保存时校验它仍有效。Agent 写仓库文件必须传 `base_version=读取结果中的 repository_version`；过期版本要求重新读取合并。原 `site-learn/sites/chaoxing.com/...` 路径归到同一份 `chaoxing/...` 文件，保留读取原文和收尾证据检查。图谱仍通过图谱工具保存，并热加载本地分支的有效版本。

有本地差异时来源标识显示 `本地修改`，清除全部差异后恢复为 `仓库`。点击来源标识打开提交历史：本地事件包含保存、迁移、冲突处理、恢复版本和保留本地改动的上游更新，详情含日期、修订 ID、父版本、基准版本和文件列表。历史与内容一起加密落盘，只在保存成功后发布；无效写入、相同内容和未变化的缓存检查不会产生提交。保留最近 200 条元数据，不额外复制旧正文。旧版本已存在的改动仅迁为一个明确的检查点，无法还原过去未记录的逐次修改。恢复仓库内容仍保留历史。

上游历史使用[提交列表接口](https://docs.github.com/en/rest/commits/commits#list-commits)，首次以当前缓存的提交 SHA 固定起点，并按网站包目录过滤，分页展示真实 Git 提交，可点击前往 GitHub 查看变更详情。记录按仓库来源、提交 SHA 和页码缓存到本地，重启后仍可读取。缓存缺页或提交 SHA 变化时按需请求；网络失败保留本地历史和已加载的远端记录。本地修订 ID 是应用生成的 SHA-256 标识，不冒充 Git SHA，也不会在 GitHub 上创建提交。

时间线右上角的刷新按钮会查询 GitHub 分支最新 SHA，并在该 SHA 上重新读取提交记录；只更新历史缓存和 `origin/<分支>` 引用，不更新网站资源快照、不合并本地修改或处理冲突。成功查询的历史起点也持久化保存，重新打开无需再次联网；网站资源实际更新后，旧的历史起点会失效。刷新失败继续显示原记录，可重试。

历史窗口按用户参考图改为 VS Code Source Control Graph 的提交图样式。分支线以 22px 行高和 11px 泳道宽度连续绘制，普通节点为实心点，合并节点为带中心点的圆环，当前版本为空心圆；远程第一父提交链固定在最左列作为蓝色主线，右侧支线按 VS Code 色板依次采用橙、粉、棕、青、紫色，并沿该支线继承到真正的共同父提交。只优先远程头节点，祖先之间按拓扑与时间排序，避免旧主线记录抢在较新的支线前面。连接采用半径 11px 的四分之一圆弧与水平线，边界切线保持竖直，不使用 S 形贝塞尔曲线；每行按实际泳道数分配图形宽度。右侧使用同色胶囊标签展示本地修改、实际分支名称和 origin/<分支>。当前没有本地差异时，本地与上游标签可以落在同一个节点。悬停详情、来源筛选和键盘操作保留。

GitHub 历史保留接口返回的真实父提交，软件本地记录使用已经保存的父版本及上游更新关系；按照子节点先于父节点的顺序布局，独立头之间优先远程主线，再考虑当前工作和时间，不再把全局时间排序直接当作 Git 祖先顺序。历史更新节点显示具体基准短 SHA，不将旧的更新事件描述成已同步最新；远程与本地基准不同时显式提示。旧内置迁移节点在标题和悬停详情中说明来源。已知共同父版本才绘制汇合线；旧迁移记录指向 bundled 版本、目录筛选跳过的提交或尚未加载的父版本只显示短延续，不伪造与相邻行的关系。加载更多后重新计算图形。

作者、完整版本号、绝对时间及文件列表仍放在悬浮卡片里，不撑开列表。首次悬停延迟 300ms，移入卡片可选择文本或打开 GitHub 更改；键盘聚焦和触屏点击也可显示，Escape 先关闭卡片再关闭窗口。筛选变化、列表滚动和卸载会清理浮层。上下方向键及 Home/End 导航记录，右方向键进入悬浮卡片。

## 验证

自动回归覆盖分支创建、重启读取、旧文件迁移、恢复官方版本、下载中的并发修改、过期写入、更新冲突、限流、离线、持久化失败、恶意路径、符号链接、截断目录和 blob 内容校验。开发桥 `health.websiteRepository` 仅暴露版本、修改/冲突数量与错误状态，不返回经验正文或账号。

原生验收已经读取到公开仓库首版 SHA，并将既有本地经验保留为分支；与官方同时变更的文件显示冲突，未自动丢弃。无需继续播放课程或提交测验来验证仓库存储。

GitHub 接口依据：[Git trees](https://docs.github.com/en/rest/git/trees)、[条件请求与限流处理](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。
