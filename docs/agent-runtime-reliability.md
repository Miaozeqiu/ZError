# Agent 运行可靠性与恢复

本次在 `dev-improvements` 增加运行检查点和纯 TypeScript 核心。Vue/store 仍负责产品界面；没有把整个项目替换成外部 Agent 框架，也没有将诊断轨迹宣称为完整事件溯源日志。

## 执行与恢复

浏览器控制权互斥：只有显式点击“取得控制权”才允许用户操作网页；悬停、点击、滚轮、拖拽、键盘和手势本身不会触发接管。macOS 的 AppKit 本地输入监视器在原生 CEF/WK 子视图收到物理事件之前拦截；CEF 同时用原生命中测试隔离网页子树，并用 DragHandler 拒绝未接管时的外部文件/链接拖放。Agent 的 CDP 输入不经过该物理输入路径。交还 Agent 时撤销网页原生文本焦点，导航栏、地址栏和标签页同步禁用；窗口拖动、展开/收起和控制权按钮仍可用。用户主动发送新消息仍按原逻辑交还控制权并读新页面。Windows/Linux 原生输入路径需要各平台单独验证。

每条助手消息的 `run` 保存版本化运行状态、预算计数、浏览器 ID 和操作回执。生命周期区分 preparing、running、waiting_video、waiting_user、interrupted、completed、blocked 和 failed。视频等待和审批等待不等于任务完成；终态不能被迟到事件重新激活。

运行检查点随 `agent_chats` 加密存储。发送网页副作用操作前必须等待检查点保存成功，保存失败则不执行。启动时将尚在运行/等待的检查点转为 interrupted，清理消息的等待显示，不恢复旧定时器或旧 ref。用户主动发送“继续/恢复/重试”等消息时建立新的运行，带入原任务目标和不确定操作；先重新读取页面。普通新问题不会自动续跑旧任务。原用户目标在恢复时独立注入，避免仅靠压缩摘要寻找目标；当前用户的新要求优先。

完成/阻塞状态必须等待保存回执，保存失败则撤回暂存的终态并进入 failed，使后续“继续”仍能恢复。保存期间的用户接管优先，迟到回执不能把 interrupted 改回 completed。

有副作用的操作先创建并确认本对话的标签，再保存带非空标签 ID 的操作记录；派发前再次核对标签未切换。旧记录若缺少标签 ID，不能以任意标签的新快照消除不确定状态，应明确报告无法核对。`browser_eval` 使用保守 AST 分类：明确的属性读取、document DOM 查询及无参数同步函数中的局部读取不记副作用；赋值、点击、未知调用等仍保存操作回执。此分类仅用于恢复流程，不是脚本安全沙箱，不替代原有 eval 策略。

网页点击/输入等操作若响应丢失，不能认定一定失败。`browser_run_status` 提供当前运行的操作 ID 和本会话标签 ID；`browser_select_tab` 只能选择当前对话拥有的现有标签。需要先在原标签 `browser_get_page` 或 `browser_screenshot` 得到新的 `observation_id`，再通过 `browser_verify_operation` 提供页面回执，确认 completed 或 not_completed。恢复与核对不扩大用户原有授权。

这是“检查点 + 重新观察 + 结果核对”，不是网页事务或恰好执行一次保证。通用网站没有幂等接口时，具体业务结果仍需模型根据页面判读；没有可靠证据应报告 blocked。不要重放提交、旧 ref 或上一段视频的监控。

## 边界

- `core/run.ts`：不依赖 Vue、浏览器或 Tauri 的状态转换、预算、错误分类和恢复信息。
- `core/controller.ts`：运行控制、操作回执及 before/after 中间件。强制检查在中间件外，中间件接收冻结的调用副本，不能修改本轮动作或跳过宿主审批/控制权/凭据检查。
- `core/tools.ts`：本轮工具注册与常用 JSON Schema 参数校验。未注册工具、非法 JSON 或不满足声明的参数不进入执行器。它不是完整 JSON Schema 引擎，新增复杂 schema 关键字时必须同步扩展校验器并补测试。
- `core/prompt.ts`：稳定排序、重复分区检查与上下文资料边界。上下文和 Skill 不会授予权限；浏览器控制及凭据 origin 校验仍由宿主执行。
- `core/experience.ts`：站点经验的验证状态。通过收尾证据得到验证时间，连续定位失败标为待复核；历史无验证信息时不假定已验证。记录随加密会话保存，历史清理后可能不再有元数据，经验正文仍保留。

## 模型

内置 Chat Completions、Responses、Anthropic Messages 走 `model/providers.ts` 的编译后适配器；保留生成模板供兼容入口使用，测试比较请求和归一化结果。只有显式自定义 JS 使用 `new Function`；它是运行在应用权限内的受信任代码，不是沙箱。

设置页和 Agent 使用同一内置适配器。设置页的 Function Calling 测试必须真正成功调用合成工具，并且最多运行四轮；普通文字回复只证明连通性。流式解析处理跨块 UTF-8/CRLF、协议失败和结束回执；未收到完整结束回执或被截断不能算成功。不自动切换到另一收费平台或扩大凭据作用域。

读取响应体或流式片段出现传输层错误且尚无可见正文时，共享最多两次当前响应重试额度，保留之前已完成的工具批次，丢弃本次未完成的工具参数；已执行工具不会重放。空白片段不算可见正文。未收到响应时不叠加连接层重试；已有正文、用户取消、过滤、长度截断和缺少协议结束回执不走该重试。重试请求和已收到的部分输出均计入运行预算。

## 预算与诊断

### 上下文

`model/contextBudget.ts` 统一执行器与输入框的文本/图片估算。模型目录可提供 `contextWindow`（兼容 `context_window`、`contextLength`、`context_length`），未知窗口按 64k 估算并在界面说明，不按型号猜测。可用输入量扣除模型输出预留和安全余量；图片统一按每张 4096 个估算 token 预留。24k 是节省上下文的软目标，真正发送前再检查完整请求（含工具定义）是否超过可用输入量；估算不是供应商 tokenizer 或计费保证。

执行器在下一次模型请求前检查上下文，在完整工具批次之间进行语义压缩，保留用户原话、最新工具批次、对应调用 ID 和协议签名。摘要只包含可见正文、参数与结果，不包含私有思考或签名。当前任务原话、清单、浏览器与最近失败由宿主独立注入，摘要不能覆盖它们。模型返回上下文超限时仅允许一次压缩恢复，恢复的是模型请求，不重放已执行工具。每轮任务最多进行 12 次轮间压缩；单次归档最多 32 个分段请求，防止反复压缩或过量归档。

软压缩阈值另按工具定义和必须保留的指令所占空间留出历史余量。压缩成功后还按实际保留量设置增长余量，避免最新批次较大时增加少量网页观察就再次归档；任何情况下完整请求仍须低于扣除输出预留后的硬上限，供应商超限恢复也不受软余量影响。

分段归档覆盖选定消息的全部文字，不再先裁掉每条消息后半段，也不先抛弃最早的归档消息。只有所有分段都成功后才更新摘要边界；失败或取消时保留原文。运行中归档使用同一模型，归档的请求和输出计入该运行预算。空闲时的会话归档是单独的后台请求。

运行中归档使用临时模型配置关闭思考，摘要要求控制在 1000 字内，输出预算最多 4096 token 且不超过所选模型配置；不修改主 Agent 或已保存的模型设置。响应因长度上限失败时显示服务端原因及实际请求上限，与内容过滤区分。自定义网关若忽略关闭思考参数，仍以其真实回执为准，不将截断当成成功摘要。若仅为软目标触发的摘要被截断，而完整请求仍在硬上限内，保留原记录继续并停止本轮后续软压缩尝试；真正超限或服务端已经拒绝上下文时必须成功压缩，不绕过硬限制，不重放操作。

原生脱敏在一次文档遍历内复用同一凭据匹配器，嵌套工具 JSON 仍递归脱敏；每次新操作重新按当前凭据构造，不跨凭据变更缓存。替换聊天文档前完成新文档脱敏，不再重复扫描随即被覆盖的旧聊天副本。加密、写入检查点和保存失败门禁保持生效。

完整脱敏工具文字保留在 `agent_chats` 的加密 transcript；显示与请求使用独立投影，不截断合法的工具参数 JSON。精简结果保留操作/观察 ID、不确定状态和 `history_ref`，可通过 `search_conversation_history` / `read_conversation_history` 在当前对话内找回原文。读取前先对完整源记录再次脱敏，再按最多 12000 字符分页，避免分页切开凭据。不能读取其他对话，也不能把历史内容当作当前页面证据。旧版已丢失的原文无法追溯恢复。

工具截图附带内部来源标记，脱敏克隆后仍能识别并省略旧截图；用户主动附带的图片不因此删除。内部来源标记不会发给供应商。`run.usage` 另记录压缩次数及最近一次压缩前后的估算用量，不保存正文到诊断轨迹。

工具图片统一请求 `high` 视觉细节，整页截图也不因 JPEG/base64 字节较多而降为 `low`。文件压缩大小不代表中文字、题号与否定词是否可读；旧截图仍按上述规则退出后续请求，避免不断累积视觉用量。

有序网页内容应按 DOM 顺序返回数组，显式绑定显示序号、原文与稳定元素 ID。`browser_eval` 在返回结果中发现至少两个 ECMAScript 整数索引键时，在工具信封的 hint 中提示键顺序可能已重排，保留原数据不自动排序或映射。检测只作有界提示，不是通用题目解析器，也不保证模型一定遵守。学习通 Skill 要求点击前核对同一容器的题号、题干和 ID，提交前按显示题号逐题核对已选答案；数字 ID 大小和题型分组都不能代表题序。

默认每次运行最多 120 次模型请求（包括重试）、200 万估算输入 token、15 万输出 token、400 次工具调用、8 次未被成功操作打断的失败，或 8 次带相同页面快照但未见变化的动作。页面无进展检测是有界启发式，不是完成证据。模型循环原有轮次/响应超时限制仍有效；视频和用户确认等待暂停响应超时。成功只读查询不清除失败动作计数。

输入按实际发送的请求文本估算，图片每张预留 4096 token；输出优先使用服务 usage，缺失时估算正文、思考和工具参数。计数不是供应商账单，不提供准确金额或跨供应商统一 tokenizer 保证。

`run.trace` 最多保留 200 条类型化诊断事件，包含计数、工具名、错误分类、状态和时间。不会记录调用参数、网页正文、聊天原文或密钥。检查点继续使用原有加密会话存储，不新增明文日志。`browser_run_status` 和测试桥 diagnostics 都能读取这些运行信息。

## 验证边界

用户明确指定编号章节时，`browser_finish.completion` 可以引用最新页面/截图的宿主观察 ID、全部指定编号和具体可见证据，确认限定任务完成。编号范围只来自当前运行原始用户目标，重启后仍可从加密会话恢复，不来自清单或模型摘要；整门课不能缩成少数章节。宿主验证本轮工具记录、观察所有者、页面、两分钟时效以及期间没有新动作/失败读取；新网页动作、失败读取或更晚页面观察会使旧证明失效。清单、活跃视频/监控、未核对操作与课程计划的门禁仍生效。不从隐藏 HTML 提示或任意 eval 自述推断完成，也不要求尚未授权执行的其他章节全部完成。完成依据是实际提交和任务状态，不能把完成等同于满分。

当前原始用户要求明确为“只读核对/复核”等任务时，收尾只表示这次查看已完成，不表示当前课程已完成。仅当本轮没有填写、勾选、导航、提交或写入工具、只读工具均已返回，且有两分钟内的真实页面/截图宿主观察，才允许按只读任务收尾。滚动可用于查看内容，但滚动后必须取得新观察；其他只读提取不因此要求重复截图。不采信模型自称只读，也不从旧任务或摘要推断。仍有未完成清单、活跃播放/监控或未完成课程计划时不能用此路径退出。含积极执行指令的混合目标不走此路径；证据不够时返回只读核对专用提示，不要求查询整门课统计。

自动回归覆盖：保存失败不派发、丢失回执不重放、同毫秒旧快照拒绝核对、跨标签拒绝核对、接管时迟到结果、恢复前新观察、预算限制、诊断不存敏感正文、原任务恢复、视频事件续跑、协议兼容和真实工具测试入口。

2026-11-02 在签名开发版 Tauri + CEF 中验收两个连续章节：视频分别自然播放 21:36 和 22:14，结束事件均触发 Agent 继续测验，两个章节均显示完成标记，限定任务成功收尾。两次提交分数分别为 50 和 100；第一次逐题复核发现两个判断题的元素 ID 与显示题序相反，按 ID 顺序配题导致答案点反。该回执保留，不重复提交；补充有序提取和提交前核对规则，并以当前已提交页面只读验证题序。

这不代表已完成整门课，也不代表修复后已重新提交验证第一份测验。切换标签、物理输入接管和重启后的页面核对仍需单独原生验收。不能用 Chromium 网页测试替代 WKWebView/CEF 原生界面验证。

macOS 主界面承载 Agent 循环，创建时设置 `BackgroundThrottlingPolicy::Disabled`（系统支持从 macOS 14 起），避免切到其他应用后被 WKWebView 默认后台暂停策略冻结。用户显式停止、人工接管和任务预算继续生效；不承诺在系统睡眠、应用退出或进程被终止后继续运行。原生验收需把主界面置于后台超过五分钟，确认桥心跳、视频进度与结束事件仍更新。

上下文专项回归还覆盖 24 个模拟章节步骤跨多次压缩、超限仅恢复一次且不重放操作、完整工具批次与签名保持、超大当前输入不发送、长参数 JSON、长消息末尾归档与分页找回、原始用户要求独立于摘要、取消与空摘要不提交、原文加密保存和显示投影分离。
