# 浏览器 Agent：iframe 修复方案

目标：在学习通的章节壳、cards、视频、文档和测验嵌套中，读到的元素、实际操作的元素、回读验证和监控指向同一个文档。

## 实施顺序

1. 统一 frame 身份：快照和定位传递 `frameId`、`loaderId`；路径和 mid 只作初次发现。文档替换后拒绝旧引用，要求重新读页。
2. 收口动作：删除丢失 frame/nth 的快捷点击和填写；每次操作重新定位，在返回的 CDP session 中执行。填写通过目标节点本身验证，支持清空和密码脱敏。
3. 修复 frame 发现：统一最大深度，隐藏框不挤占可操作框额度；按所属页面的 frame 树识别跨进程 target，避免混入其他标签。
4. 动作后读取目标 frame，包括同进程嵌套框；跨域读取与媒体探测通过 frame 的独立执行上下文完成。
5. 回归覆盖：重复 ID、多层路径、隐藏框、跨域 session、文档重建、输入验证、监控绑定。执行 Vitest、TypeScript 检查和 Rust 检查/测试。

## 验收

- 同名按钮/输入框不会因快捷路径跳到别的 frame。
- 六层嵌套与大量隐藏框后的可见任务仍可发现、定位。
- 已销毁或导航过的 frame 引用失败并提示刷新，不退回其他同名元素。
- 输入结果来自被操作的节点；清空也能通过验证；密码不写入工具结果。
- 监控指定视频时不擅自改监控其他视频；跨域不依赖父页面访问子 document。

现有 CEF 窗口、登录态及用户未提交的界面修改保留。实现继续使用现有 Rust CDP，不增加 Node sidecar。

## 本轮实现

- `cef/frames.rs` 统一枚举当前页面所属的 frame，按父子顺序绑定 OOPIF session，复用会话；跨域 DOM 读取在 frame 的独立上下文中执行。
- 快照、ref 缓存和定位传递 `frameId/loaderId`，文档更换后拒绝旧引用；新快照的 ref 编号不复用。移除了从页面全局变量回捞旧 ref 的路径。
- 点击和填写统一走重新定位。填写聚焦、输入及回读固定在同一 backend 节点和 session，校验实际值，支持清空和密码脱敏。
- frame 发现与定位统一支持最多 16 层；发现预算 2048 个 frame、操作预算 128 个可见 frame，隐藏框不占可见额度。重复 URL 的 frame 按身份保留。
- 动作后读取实际目标 frame；HTML 读取、指定 frame eval、多 frame 探测和媒体监控使用同一 frame 发现入口。
- 视频监控绑定具体 frame、文档和媒体序号；学习通额外用 mid 关联任务点。切换监控后丢弃旧请求迟到的进度回执。

## 验证结果

- Vitest：61 个文件、303 项测试通过，包括运行时真实快照脚本的隐藏框、六层嵌套及密码脱敏用例。
- Rust：50 项单元测试通过；`rust:check` 通过。
- Vite 生产打包通过。
- 完整 `vue-tsc` 尚有 68 条既有类型诊断；与修改前的隔离副本对比，没有新增诊断。

学习通已登录页面的实机端到端回归尚未覆盖。本轮不把本地脚本及模拟协议测试视为整门课程自动执行的实机验收。
